# fakao-importer

## 目标

把用户课程、讲义、笔记和题库转成可审核的原始资料与结构化题目，不改变原文。

## 首选载体：Web 工作台

用户要导入竹马错题时，优先运行 `./fakao ui` 打开竹马导入页（`/zhuma`）：网页承载两阶段交互（打开浏览器 → 用户登录 → 点"我已登录"后台导出 + 实时日志），比终端对话更直观。终端流程（`./fakao zhuma`）保留给 CLI 用户和 Agent 无浏览器环境的场景。本地文件导入（Markdown/笔记）仍按下面的通用导入流程在对话中完成。

## 竹马错题导入（两阶段交互）

用户说"导入竹马错题"时，运行 `./fakao zhuma`（auto 智能模式）：

1. **已有本地登录态** → 直接导出错题 → 自动跑错误分析 → 生成今日任务，全程无需用户操作。
2. **无登录态或登录态失效** → 脚本自动打开临时浏览器后**立即返回**（不挂起、不后台等待）。
   此时必须向用户明确提示：
   > 请在弹出的浏览器窗口中登录竹马并完成验证码；登录完成后请回复「1」或「我已完成登录」。

3. 用户回复「1」或「我已完成登录」后，运行 `./fakao zhuma login`：脚本连接浏览器取回登录态
   → 保存到本地 → 导出错题 → 错误分析 → 生成今日任务。

**关键约束**：

- 不要在登录等待期间阻塞任务或长时间挂起；`open` 后脚本立即返回，由 Agent 提示用户回复。
- 登录页弹出后，提示语中**不得出现** cookie、token、接口、JSON 等技术概念。
- 若脚本提示"检测到已打开的浏览器"（如上次未关闭），直接复用，不要重复打开。

## 凭据与登录态（落盘复用）

- 登录态保存到 `00_系统与用户/zhuma_session.json`（权限 600，该目录已被 `.gitignore`
  保护，凭据**永不进入 git 仓库**）。
- 会话有效期内重复导入**不再要求用户重新登录**；只有接口确认失效（自修复失败）才重新走登录。
- 临时浏览器保留复用：`login` 成功后浏览器不自动关闭，用于后续接口签名刷新；用户不需要时
  可运行 `./fakao zhuma close` 关闭。
- 不得把凭据写入任何 git 追踪文件、不得在日志/对话中打印凭据内容。

## 接口自修复

- 脚本内置自修复：接口返回非 200（如签名头过期、路径变更、风控）时，若浏览器仍打开，
  会自动从浏览器实时请求中捕获最新签名头与接口路径，刷新本地会话后自动重试。
- 自动修复成功则继续导出；失败才提示用户重新登录。
- 若脚本提示"接口路径可能已变更"且修复无效，按 `fakao-update` 流程检查上游仓库是否有更新。

## 通用导入流程（本地文件）

1. 扫描格式并提取章节、题干、选项、答案、解析和来源位置。
2. 去重并标记缺失字段、解析失败、来源不明和可能过时的内容。
3. 本地资料先写入 `01_待导入资料` 或结构化待审核结果，用户确认后再进入正式库。

## 约束

任何题目和规则都必须保留 `source_file`、法律版本和 `审核状态`。不把 AI 推断当成标准答案。
